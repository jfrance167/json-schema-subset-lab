## Exact grammar and semantics

Boolean definition true passes any instance; false fails with false-schema. Empty object passes. Supported definition keys only type,enum,required,properties,additionalProperties. Unknown keys (including metadata, $schema/$ref/$defs, pattern, format and combinators) collect unsupported rows, no execution/lookup. This conservative refusal differs from general JSON Schema's treatment of unknown annotations and is an explicit product subset policy.

Type value: recognized seven string names object,array,string,number,integer,boolean,null or a nonempty unique array of recognized strings≤7. Empty array excluded by this bounded profile; no claim based solely on prose keyword specification. In admitted integer-only instances, number and integer both accept exact int, never bool. This does not model fractional/decimal numbers or claim JSON Schema itself restricts number range.

Enum value exact list length0..32, any admitted bounded JSON values, duplicates allowed and counted. Equality exact JSON kind/code points recursively; dict member order irrelevant, list order significant; false≠0 and true≠1. No schema interpretation inside enum objects: an enum literal containing $ref/properties is ordinary literal data. Empty enum never matches. Nonempty/unique enum entries are recommended rather than mandatory in2020-12; do not turn them into malformed-schema claims.

Required exact list≤16 distinct exact strings, including empty name; empty list allowed. For object instances only, membership matters: null/false/zero satisfy presence. No implicit object type. Properties exact map≤16 names to exact boolean/object schemas; validate every nested schema even if the member is absent or instance is not an object. At evaluation recurse only on present object members in codepoint-sorted name order; absence alone does not fail properties.

AdditionalProperties true/absent permits extras, false fails each instance name absent from properties at the same schema object, regardless of whether that declared property's child validation passes. No patternProperties/annotation-tracking interaction exists. On nonobjects required/properties/additionalProperties are neutral; definition shape/support assessment still occurs. A boolean value is supported. An object schema value is generically and recursively grammar-checked but marks that keyword variant unsupported (reason nonboolean-additional-schema); scalar/list/null values are malformed definition2. Even empty additionalProperties object is unsupported under this exact profile rather than silently treated as true.

All applicable supported constraints are conjunctive and evaluated without short-circuit after a known failure, preserving independent issue provenance. At each object definition evaluate type,enum,required (missing names sorted), present properties children sorted, then extra-property failures sorted. Boolean false has one issue; passing/irrelevant keywords produce no issue. There is no separate array item schema evaluation, annotations or validity of actual systems.
